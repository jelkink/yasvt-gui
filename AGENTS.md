# AGENTS.md

GTK 4 vocabulary trainer in C, ported from yasvt-python. See [README.md](README.md) for behaviour.

## Build and test

- `make` builds `build/yasvt-gui`. The code must compile without warnings (`-Wall -Wextra`).
- No test suite. To test the GUI offscreen, run `gtk4-broadwayd :5`, then a small harness that `#include`s `src/gui.c` with `GDK_BACKEND=broadway BROADWAY_DISPLAY=:5`.
- Point `XDG_DATA_HOME`, `XDG_CONFIG_HOME` and `XDG_CACHE_HOME` at temporary directories so the user's real progress, settings and audio cache are never touched.

## Do not change the in-session sequencing

The order of words during a session works exactly as the user wants. Do not modify it, or anything it depends on, without being explicitly asked:

- `wordlist_reinsert_current()` in `src/wordlist.c` (re-insert window, score-based position, `REINSERT_WINDOW`).
- `word_average_score()`, `word_update_score()` and the 8-bit `Word.history`, which feed it.
- The rule that the head of the queue is the current word, and that each answer re-inserts it.

Keep the two kinds of history separate:

- **In-session score** (`Word.history`): starts at 0 every run and drives the queue. Never seed it from saved progress.
- **Persistent progress** (`src/progress.c`, `progress.txt`): only used for the *initial* order after opening a file, starting without a file, **Reverse**, or a filter change. It must never influence the order once the session is running.
- **Shuffle** is a plain random shuffle (`wordlist_shuffle`). It must not use progress.

## Data model

- `app->all` owns every loaded `Word`. `app->list` is the queue: the words passing the language filter, **not owned** (its array has no free function). To delete a word, steal it from the queue and remove it from `app->all`.
- Languages are lowercase names from the CSV header, or chosen in a dialog when the header does not name two known languages (`wordlist_is_known_language`: the speech languages plus `extra_languages`); the choice is stored per file path in settings.ini. Loading files is therefore asynchronous (`LoadJob` in gui.c). The first CSV column is the language the user types (`target`), the second is the one shown (`source`).
- Chinese (language exactly `chinese`) is stored as simplified. Typed answers are converted to simplified before comparing; traditional is only a display option (`word_set_traditional`).
- Progress entries are keyed by an MD5 of both languages and both words, per direction. A word with `last_seen == 0` is registered but still counts as new.
- Progress is only written by `progress_flush()` (30 s timer, closing the app) and by the editor and registration; `progress_record()` just marks it dirty. Per-word `ease` only affects the persistent interval, never the in-session score.
- The statistics and progress editor windows live in `src/progress_ui.c`; the editor reports edits and deletions through hooks so that `app->all` and the queue stay in sync.

## Conventions

- Audio plays through `curl` and `mpv`, with clips cached in `~/.cache/yasvt-gui/`. Native languages (settings) get no automatic audio.
- `src/pinyin_table.c` and `src/hanzi_table.c` are generated by the scripts in `tools/`. Do not edit them by hand.
- Keep changes small and in the existing style. Update README.md when behaviour visible to users changes.
